# 0.2.4 — 2026-08-09

## Added

- **Test suite** — the `smoke`, `fuzz`, and `integration` Vitest projects (previously scaffolded but disabled) are active alongside `unit`; `npm test` now runs all four. New `test:coverage` script, backed by `@vitest/coverage-istanbul`.

## Fixed

- **`medcode_map_codes`'s `rxcui_to_ingredients`/`rxcui_to_brands`** omitted the target's RxNorm name — `mapDrug` selected snake-case `target_type` from `rxnorm_rel` but read camelCase `r.targetType`, always `undefined`. Now joins each edge's target back to `codes` and returns its description, on both `structuredContent` and `content[]`. ([#19](https://github.com/cyanheads/medical-codes-mcp-server/issues/19))
- **`medcode_map_codes`'s `rxcui_to_ndc`** returned every package NDC for a product unbounded — one bundled RXCUI carries 3,497. Now paginates through the shared `fetchPage` primitive alongside `children` and `name_to_rxcui`, with `nextCursor` continuation and an `ORDER BY ndc` total order. ([#20](https://github.com/cyanheads/medical-codes-mcp-server/issues/20))
- **`medcode_get_code`'s NDC normalization** accepted hyphenated segments with undersized widths (e.g. `2-152-1`), left-padded them, and could resolve to an unrelated real product. `ndcCandidates` now matches the segment widths as an exact tuple against the four FDA configurations (`4-4-2`, `5-3-2`, `5-4-1`, `5-4-2`) instead of independent per-segment upper bounds. ([#23](https://github.com/cyanheads/medical-codes-mcp-server/issues/23))
