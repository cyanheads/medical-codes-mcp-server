# 0.2.6 — 2026-08-09

## Added

- **`medcode_map_codes` hits carry `conceptType`** on `rxcui_to_ingredients`/`rxcui_to_brands` results — `IN`/`PIN`/`MIN` for ingredients, `BN` for brands — sourced from `rxnorm_rel.target_type`. Separates a combination product's substances from the `MIN` grouping concept that names the combination itself; 6,141 bundled products carry at least one `MIN` ingredient edge that a flat hit list previously counted as an extra substance. ([#28](https://github.com/cyanheads/medical-codes-mcp-server/issues/28))

## Changed

- **`medcode_map_codes` `ndc_to_rxcui` hits** now carry the target's RxNorm `description`, resolved through the same concept projection as `name_to_rxcui`. Previously a bare RXCUI, requiring a second `medcode_get_code` call to learn what the package was. ([#27](https://github.com/cyanheads/medical-codes-mcp-server/issues/27))
- **`medcode_search_codes`'s `chapter` filter** now upper-cases the trimmed value to match how chapters are stored, and `appliedFilters.chapter` echoes the value that actually ran. Previously a lowercase chapter zero-hit a valid search. ([#30](https://github.com/cyanheads/medical-codes-mcp-server/issues/30))

## Fixed

- **`medcode_map_codes`'s paginated directions** (`name_to_rxcui`, `rxcui_to_ndc`) no longer report a `cursor` past the last page as `no_mapping`. `CodeIndexService` now probes for any row at the unpaged query before inferring the source is unmapped from an empty page, and the response distinguishes the two causes (`MapPage.pastEnd`) so `medcode_map_codes` can word the notice correctly instead of reusing the no-edge wording. `docs/design.md`'s error-contract table is corrected to match: `no_mapping` fires when the source itself doesn't resolve, not when it resolves with no edge or an out-of-range page. ([#26](https://github.com/cyanheads/medical-codes-mcp-server/issues/26))
- **`medcode_map_codes`'s `rxcui_to_ndc`/`rxcui_to_ingredients`/`rxcui_to_brands`** no longer throw `no_mapping` for a resolvable RXCUI that legitimately has no edges of that relation — every `IN`/`PIN`/`MIN`/`BN` concept carries no `has_ingredient` edge and no package NDC by definition. `no_mapping` is now reserved for an RXCUI absent from the bundled index; a resolvable concept with no edges is a successful empty result with a direction-specific notice. ([#31](https://github.com/cyanheads/medical-codes-mcp-server/issues/31))
- **`medcode_get_code`/`medcode_check_code`/`medcode_map_codes`** now decode the header rows the index materializes — the 17 HCPCS letter buckets (`J`, …) and the 914 three-character ICD-10-PCS table rows (`001`, `00B`, …) — without requiring an explicit `system`. `resolveSystems()` falls back to full DB-membership matching when no shaped candidate matches, since `detectSystems()` only describes complete code shapes. ([#29](https://github.com/cyanheads/medical-codes-mcp-server/issues/29))
