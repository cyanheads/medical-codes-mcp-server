# 0.2.5 — 2026-08-09

## Changed

- **`medcode_get_code`'s text (`content[]`) hierarchy render** now gates each field on presence rather than truthiness: an empty `children` array renders `**Children (0):**`, and `childrenTruncated: false` renders `_Complete: no further children exist beyond those listed._`. Previously both were dropped whenever falsy, so a code with a genuinely empty and complete child set rendered identically to one where hierarchy wasn't requested at all. ([#21](https://github.com/cyanheads/medical-codes-mcp-server/issues/21))
- **`medcode_search_codes`'s `chapter` filter** now trims surrounding whitespace and treats a blank/whitespace-only value as omitted; the applied value (not the raw input) is echoed in `appliedFilters.chapter`. Previously `''`/`'   '` were passed straight to the SQL predicate and zero-hit against every row. ([#22](https://github.com/cyanheads/medical-codes-mcp-server/issues/22))

## Fixed

- **`medcode_browse_hierarchy`** on `ICD10PCS` rejects a `node` with a character outside the 34-value axis alphabet (`0-9`, `A-Z` minus `I`/`O`) and, separately, an in-alphabet node that no bundled code begins with — both now throw `unknown_node` with a reason naming which check failed. Previously either case fell through to an empty-axes success carrying the same "positions 2-7 are context-dependent" notice a real partial path gets. The prefix check seeks the `codes` table via a half-open range (`code >= prefix AND code < prefix-upper-bound`) rather than `GLOB`, so it uses the `(system, code)` primary key instead of a partition scan. ([#24](https://github.com/cyanheads/medical-codes-mcp-server/issues/24))
- **Search queries containing an embedded NUL byte (`\u0000`)** reached FTS5's `MATCH` parser raw and threw `SQLiteError: unterminated string`, since FTS5 re-parses its query argument as a miniature query language and a NUL terminates that parse. `tokenizeQuery` now normalizes NUL to a token separator alongside the existing FTS operator-character strip, so `diabetic\u0000neuropathy` still resolves to a two-term search instead of throwing or being silently dropped. ([#25](https://github.com/cyanheads/medical-codes-mcp-server/issues/25))
