# 0.2.7 — 2026-08-09

## Added

- **`alsoInSystems`** — optional output field on `medcode_get_code` (per `found[]` entry), `medcode_check_code`, and `medcode_map_codes`'s `parents`/`children` directions. Names the other bundled systems holding the same code string when the shape pass narrowed to one real member over another, so a successful answer to a colliding string is never mistaken for the only one; `format()` renders an `**Also in:**` line on all three so `content[]`-only clients see it too. Covers the 60 three-character ICD-10-PCS table rows that are also ICD-10-CM categories (`B00` is both "Herpesviral [herpes simplex] infections" and "Imaging, Central Nervous System, Plain Radiography"). No existing resolution changes — `resolveSystems()` still picks the same system it did before, `alsoIn` is a disclosure alongside that choice, verified by replaying 18,541 inputs across five operations against the prior release with no diff besides the intentional wording change below. ([#32](https://github.com/cyanheads/medical-codes-mcp-server/issues/32))

## Changed

- **`medcode_get_code`'s and `medcode_check_code`'s not-found reason** — corrected from `"<code>" does not match the shape of any bundled code system` to naming membership as the arbiter (`"<code>" is not present in any bundled code system … and matches no bundled code shape`). The old wording described `resolveSystems()` before 0.2.6 widened it to full DB-membership fallback; it no longer matched the actual logic.

## Fixed

- **Test-fixture builder** (`tests/helpers/index-fixture.ts`) — no longer races Vitest's parallel workers to build `tests/fixtures/medical-codes.fixture.db` in place. Each worker now builds to a private `.tmp` scratch path and publishes with `linkSync`, so the shared inode is created once and never replaced; a sibling worker that loses the race adopts the winner's file instead of reading a half-written one. Reproduced on unmodified 0.2.6 at 5 of 6 cold runs (`disk I/O error`, `vtable constructor failed: codes_fts`). A new `assertFixtureCurrent()` check also refuses a cached fixture older than `scripts/build-fixture-db.ts`, so a stale working-copy DB fails loudly instead of silently missing rows the tests expect.
