# 0.5.1 — 2026-10-29

## Added

- **`medcode_get_code` `deferred`** (#68): each surface of a reply (`structuredContent` and the `content[]` text) is held to 24,000 bytes; inputs past it come back unprocessed, in request order, in the optional `deferred` array. Re-call with `codes: deferred` and the same `system` and `includeHierarchy` until it is absent.
- **`medcode_map_codes` `conceptType` on `name_to_rxcui` and `ndc_to_rxcui` hits** (#67): the concept's term type (`SCD`, `IN`, `SBD`, …), as `rxcui_to_ingredients`, `rxcui_to_brands`, and `class_to_rxcuis` already return.

## Changed

- **`medcode_browse_hierarchy` PCS notices and server `instructions`** point a three-character table row to `medcode_map_codes` `children` for its complete codes (#66).

## Fixed

- **ICD-10-PCS table rows are parents of their codes** (#66): `medcode_map_codes` `children` on `0DT` lists the complete codes beginning with it, `parents` on `0DTJ4ZZ` returns `0DT`, and `medcode_get_code` `includeHierarchy` reports both. A table row now decodes with `header: true` and checks as `valid_header` rather than `valid_not_billable`.
- **ICD-10-CM placeholder-X codes name a bundled parent** (#72): `S82.66XA` has parent `S82.66`, which lists it among its `children`, instead of the absent `S82.66X`.
- **A dotted all-digit value is no longer read as an RXCUI** (#69): `724.2` decoded to naloxone (RXCUI 7242) on 0.5.0. It now misses on every tool, and `250.00`-style values (`NNN.NN`, `NN.NN`) add that ICD-9-CM is not bundled. A leading or trailing dot (`6809.`) still resolves.
- **An ICD-10-PCS section value passed as a code** (#73), such as `0` under `system: "ICD10PCS"`, is named as a section pointing to `medcode_browse_hierarchy`, not as a possible CPT code.
