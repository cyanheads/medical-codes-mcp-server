# 0.5.2 — 2026-11-16

## Changed

- **`medcode_search_codes` ranks a query that repeats a term as it ranks the query with that term once.**
- **Tool and field descriptions** state the ICD-9-CM rule, the 64-character code-input and echo bound, the 1,000-term search bound, and the past-the-end page notice, and the `medical-codes-guide` skill follows the ICD-9-CM rule (no schema constraint or output field changes).
- **Framework** `@cyanheads/mcp-ts-core` 0.13.18 → 0.13.22: framework skills, `scripts/`, the changelog template, and `.env.example` (`MCP_JWT_EXPECTED_AUDIENCE`, `MCP_JWT_EXPECTED_ISSUER`) re-synced.

## Fixed

- **Values in ICD-9-CM form resolve in no bundled system** ([#71](https://github.com/cyanheads/medical-codes-mcp-server/issues/71), [#74](https://github.com/cyanheads/medical-codes-mcp-server/issues/74)): `NN.N(N)`, `NNN.N(N)`, and `ENNN.N` with stem 000–030 or 800–999 miss on every tool, with or without `system`, naming ICD-9-CM as not bundled; `medcode_browse_hierarchy` answers `unknown_node`. `E880.9` had decoded as ICD-10-CM `E88.09` and `00.1` as the ICD-10-PCS row `001`.
- **A code input longer than 64 characters once trimmed is not looked up** ([#75](https://github.com/cyanheads/medical-codes-mcp-server/issues/75)): `medcode_get_code` `codes`, `medcode_check_code` `code`, `medcode_browse_hierarchy` `node` outside RxNorm, and `medcode_map_codes` `from` on every direction but `name_to_rxcui`. Every echo of a caller value in a miss, notice, `notFound`/`deferred` row, `appliedFilters.chapter`, or log field carries at most its first 64 trimmed characters plus `…`.
- **A `medcode_get_code` overlong miss's `reason` names neither the value nor its length** ([#75](https://github.com/cyanheads/medical-codes-mcp-server/issues/75); the issue asked for the length): a cut value returned in `deferred` and re-sent misses with the same entry. The other tools' messages name the length.
- **`medcode_search_codes` answers a query of any number of terms**; it failed with an internal error past about a thousand terms.
- **A `medcode_search_codes` term or `medcode_map_codes` `name_to_rxcui` name whose escaped `LIKE` pattern passes SQLite's 50,000-byte limit no longer fails with an internal error.** Search answers from its prefix tier alone and `name_to_rxcui` answers its usual `no_mapping`; 0.5.1 failed the same way.
- **A `medcode_search_codes` cursor past the last page of a query that matches** gets a notice saying so and to re-call without a cursor, not "No codes matched". The empty-page `content[]` line reads "No codes on this page." for both causes.

## Security

- **`medcode_search_codes` applies at most its first 1,000 distinct terms** and counts a repeated term once; its `notice` says how many of the query's terms were applied.
