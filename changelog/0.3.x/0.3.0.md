# 0.3.0 — 2026-09-24

Breaking for callers that send `system`, `limit`, or `cursor` to a `medcode_map_codes` direction that ignores it, read RxNorm `billable`/`shortDescription`, match on `medcode_check_code`'s status, or pass unusual NDC spellings to `ndc_to_rxcui`.

## Changed

- **`medcode_map_codes` rejects fields a direction does not use** with `field_not_applicable` (`InvalidParams`), naming them in `data.fields`: `limit` or a non-empty `cursor` on any direction but `children`/`name_to_rxcui`/`rxcui_to_ndc`, and a `system` other than `RXNORM` on the drug directions. Drop the named fields and re-call ([#36](https://github.com/cyanheads/medical-codes-mcp-server/issues/36)).
- **RxNorm `billable` is `null`** on `medcode_get_code` and `medcode_search_codes` rows (rendered `billable: n/a`), and **`medcode_check_code` answers a current RxNorm concept `valid`** with `billable: null` and no `whyNot`, where it returned `valid_not_billable`. Treat `valid` as the verdict for a system with no billing concept. `medcode_browse_hierarchy` advertises `billable` as nullable too, though it never returns an RxNorm row ([#37](https://github.com/cyanheads/medical-codes-mcp-server/issues/37)).
- **RxNorm `shortDescription` is `null`** — RxNorm publishes a single name; the term type it used to repeat is in `chapter` ([#42](https://github.com/cyanheads/medical-codes-mcp-server/issues/42)).
- **`ndc_to_rxcui` reads only FDA segment configurations** (4-4-2, 5-3-2, 5-4-1, 5-4-2) or bare 10/11 digits, the spellings `medcode_get_code` decodes; any other separator or segment width no longer resolves by having its digits stripped. Re-send the NDC as printed on the package ([#35](https://github.com/cyanheads/medical-codes-mcp-server/issues/35)).
- **RxNorm text matching reads the drug name only**: `medcode_search_codes` and `name_to_rxcui` no longer match a concept on its term type (`SBD`, `in`). Narrow by type with the `chapter` filter ([#45](https://github.com/cyanheads/medical-codes-mcp-server/issues/45)).
- **`medcode_search_codes` with `billableOnly` on RxNorm** returns a notice naming the filter as the cause, since it excludes every RxNorm concept ([#37](https://github.com/cyanheads/medical-codes-mcp-server/issues/37)).
- **Each tool carries its own `title`** (`Get Medical Code`, `Search Medical Codes`, `Check Medical Code`, `Map Medical Codes`, `Browse Code Hierarchy`, `List Code Systems`) instead of the server name ([#41](https://github.com/cyanheads/medical-codes-mcp-server/issues/41)).

## Fixed

- **A bare integer no bundled system holds is named as a possible CPT / HCPCS Level I code**, which is out of scope, on `medcode_get_code` misses and on `medcode_map_codes` `parents`/`children`/`rxcui_to_*`, with a recovery to `medcode_search_codes`. An NDC sent to those `medcode_map_codes` directions is named as an NDC and sent to `ndc_to_rxcui` ([#38](https://github.com/cyanheads/medical-codes-mcp-server/issues/38)).
- **A code-system name in `medcode_map_codes` `from`** (`ICD10CM`, `ICD-10-CM`, `HCPCS Level II`, …) is reported as a system, not a code, with a recovery showing where the code and the system go ([#39](https://github.com/cyanheads/medical-codes-mcp-server/issues/39)).
- **`medcode_map_codes` `parents`/`children` on an RxNorm concept** says RxNorm concepts have no code hierarchy and points at the `rxcui_to_*` directions, instead of calling the concept top-level or a leaf ([#44](https://github.com/cyanheads/medical-codes-mcp-server/issues/44)).
- **An `ndc_to_rxcui` miss** says whether the spelling is malformed or a well-formed NDC no bundled drug maps to, and recovers to the package label or `name_to_rxcui` rather than to `medcode_get_code` ([#50](https://github.com/cyanheads/medical-codes-mcp-server/issues/50)).
- **`medcode_check_code` recognizes an NDC**: `unknown_code` says the value is a National Drug Code, names the RxNorm product it decodes to, and recovers to `medcode_get_code` / `ndc_to_rxcui` ([#43](https://github.com/cyanheads/medical-codes-mcp-server/issues/43)).
- **Misses under an explicit `system` name the bundled system that does hold the code** on `medcode_check_code` and `medcode_get_code`; the CPT hint fires only for a bare integer no system holds ([#48](https://github.com/cyanheads/medical-codes-mcp-server/issues/48)).
- **`medcode_get_code` `no_codes_found` under an explicit `system`** names that system rather than "any bundled system", and lists held-elsewhere codes, out-of-scope bare integers, and NDCs the explicit `system` kept from the NDC decode ([#49](https://github.com/cyanheads/medical-codes-mcp-server/issues/49)).
- README: NLM attribution statement for the RxNorm data, and the VS Code install link now encodes the `/` in the package name. RxNorm sourcing prose in `docs/design.md` and the ingest script comments describes the RxNav-sourced normalized set, not the RRF prescribable subset.
