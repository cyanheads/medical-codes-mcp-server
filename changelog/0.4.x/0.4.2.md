# 0.4.2 — 2026-10-25

## Changed

- **Bundled index rebuilt** ([#47](https://github.com/cyanheads/medical-codes-mcp-server/issues/47)): ICD-10-CM and ICD-10-PCS FY2027, HCPCS 2026 October (effective 2026-10-01 – 2026-12-31), RxNorm and RxClass snapshots of 2026-10-25. With the new HCPCS release, undotted `M0231`, `M0234`, and `J9601` exist in both ICD-10-CM and HCPCS and return `ambiguous_system` without a `system` (dotted `M02.31` still resolves to ICD-10-CM); the RxNorm snapshot retires 407 concepts present in the previous index.
- **`medcode_get_code` fails `ambiguous_system` (-32602) when every requested code is ambiguous** ([#58](https://github.com/cyanheads/medical-codes-mcp-server/issues/58)), with the union of the systems in `candidateSystems`; it was `no_codes_found` (-32001). A batch mixing ambiguous and absent codes keeps `no_codes_found` and names each ambiguous code with its systems.
- **HCPCS billability is read against the UTC date of the call** ([#64](https://github.com/cyanheads/medical-codes-mcp-server/issues/64)): a termination date is the last valid day. `medcode_check_code` returns `terminated` only after it and `valid_billable` before, with the date in `whyNot`; `billable` on `medcode_get_code` / `medcode_search_codes` / `medcode_browse_hierarchy` and `billableOnly` search follow.
- **Error and recovery text no longer wraps field names in backticks** ([#63](https://github.com/cyanheads/medical-codes-mcp-server/issues/63)); framework 0.13.16 escapes error text in `content[]`, which would show them literally.
- **`scripts/build-index.ts`** ([#47](https://github.com/cyanheads/medical-codes-mcp-server/issues/47)): `--fy` is required and labels ICD-10-CM/PCS only, `--year` is removed, the HCPCS release label and dates come from the quarterly file name, and right-trimmed HCPCS rows keep their long descriptions.
- **Framework** `@cyanheads/mcp-ts-core` 0.13.14 → 0.13.16: framework skills and `scripts/devcheck.ts` re-synced.
- **Bun** 1.4.2 → 1.4.4 in `packageManager`, the Dockerfile, and the README badge.

## Fixed

- **`medcode_check_code` with no `system` names every system a missing code's shape fits** ([#59](https://github.com/cyanheads/medical-codes-mcp-server/issues/59)) in its `unknown_code` miss, as `medcode_get_code` does; a bare integer no system holds gets the CPT / HCPCS Level I sentence.
- **A dotted ICD-10-CM code (`A01.00`) resolves to ICD-10-CM** ([#61](https://github.com/cyanheads/medical-codes-mcp-server/issues/61)) when its undotted string is also an HCPCS code; the other holder rides in `alsoInSystems`. Undotted `A0100` still returns `ambiguous_system`.
- **`medcode_map_codes` `rxcui_to_*` misses name the system that holds the source** ([#62](https://github.com/cyanheads/medical-codes-mcp-server/issues/62)) instead of "No bundled code matches", and recover to `medcode_get_code` or the hierarchy walk.
- **`content[]` reads back as `structuredContent` carries it** ([#63](https://github.com/cyanheads/medical-codes-mcp-server/issues/63)): every code, description, RxNorm/RxClass name, release field, and echoed input the tools did not write renders through the `_render.ts` seam; notices are escaped for `content[]` only.
