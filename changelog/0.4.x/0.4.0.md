# 0.4.0 — 2026-09-24

## Added

- **`medcode_map_codes` `rxcui_to_classes` and `class_to_rxcuis`**: an RXCUI to its RxClass classes, and a class ID to its direct member RXCUIs; both paginate. Each hit carries `classType`, `source`, and `relation`, and a `ci_` relation is a contraindication, not an indication ([#34](https://github.com/cyanheads/medical-codes-mcp-server/issues/34)).
- **`rxcui_to_classes` on a drug product** also returns its ingredients' classes, naming the ingredient in `via`. DEA schedules are recorded only on products and VA classes almost only there (46 of the 19,704 VA edges sit on ingredient concepts), so map a product for those.
- **`classType` input** (`EPC`, `MOA`, `PE`, `PK`, `TC`, `CHEM`, `DISEASE`, `VA`, `SCHEDULE`, `CVX`) narrows the two class directions; any other direction rejects it with `field_not_applicable`.
- **`medcode_list_systems` `classLayer`**: the layer's class and edge counts, and per source its RxClass version (null for `CDC`), classes, edges, and fetch date. It is null on an index without the layer, where the class directions fail with `direction_unavailable`.
- **Bundled RxClass sources**: `MEDRT`, `FDASPL`, `FMTSME`, `VA`, `RXNORM` (DEA schedules), and `CDC` (CVX vaccine codes), 20,707 classes and 86,837 drug–class edges. Excluded: `ATC`/`ATCPROD` (WHO terms), `SNOMEDCT` (SNOMED CT Affiliate license), and `DAILYMED` (repeats 8,694 of its 8,710 edges from FDASPL, publishes no version).
- **`scripts/ingest/fetch-rxclass.ts`** caches RxClass at build time, after the RxNav fetch; `scripts/build-index.ts` bakes that cache into the index.

## Changed

- **Bundled index rebuilt** from the same FY2026 ICD-10-CM/PCS, 2026 HCPCS, and June 2026 RxNorm sources plus the class layer; code-system content is unchanged. In `medcode_list_systems`, RxNorm's `builtAt` is its RxNav snapshot date (2026-06-22), and the other systems' `builtAt` is the rebuild time (2026-09-24).
- **The index is VACUUMed** after the FTS optimize, so it ships with no free pages ([#46](https://github.com/cyanheads/medical-codes-mcp-server/issues/46)).
- **`.mcpbignore`** keeps `tests/`, `coverage/`, `.sources/`, `src/`, `scripts/`, `docs/`, and other build-only paths out of the `.mcpb`; `.dockerignore` keeps `.sources/` out of the image build context ([#54](https://github.com/cyanheads/medical-codes-mcp-server/issues/54)).

## Fixed

- **RxNorm's `builtAt`** is the time the RxNav snapshot was fetched, read from the fetcher's `meta.json`, not the build time, so a rebuild from the same snapshot reports the same date ([#55](https://github.com/cyanheads/medical-codes-mcp-server/issues/55)).
- **A code-system name sent as `from` on a drug direction** recovers to the one input that direction takes — a drug name, an NDC, or an RXCUI — rather than offering all three ([#56](https://github.com/cyanheads/medical-codes-mcp-server/issues/56)).
- **`MEDCODE_MAX_RESULTS`** is described as the default page size when a call sends no `limit` (search, browse, and the paginated `medcode_map_codes` directions) and the number of children `medcode_get_code` attaches with `includeHierarchy`, not a search/browse cap.
- README: a prebuilt index comes from the npm package or the `.mcpb` asset on each GitHub Release, which holds it at `data/medical-codes.db`.
